01 / The problem

Does this still need a decision?

The heading says “Open decisions”. The content gives instructions and says they came from explicit answers. The reader has to guess which one to believe.

One section, two conflicting messages

A human needs to know whether to answer something. An implementing agent needs to know whether to follow a choice or make one.

The current data stores chosen text, a reason and an optional source. It has no open/decided status, decision owner or approval record.

02 / Option 1 · Change the heading

Agreed decisions

Keep the current cards and replace the misleading heading.

Smallest change

It immediately tells the human these examples have already been decided. Existing plans need no changes.

Where it falls short

“Agreed” can imply human approval. The app cannot verify that from these records. It also leaves an agent to infer what a recorded decision means for implementation.

Agent treatment: explain in the tool description that required decisions should be followed.

03 / Option 2 · State what to do

Decisions to follow

Give the section a clear purpose, with the choice and its reason together.

Recommended · implemented in the draft PR

A clear instruction for both readers

The human can see that these are choices in the current plan. The agent gets a direct instruction to follow them. Plain text and spacing replace the highlighted cards.

The heading does not claim who approved the choices. It does not claim that all questions elsewhere have been answered.

Why I prefer it

It answers the actual question without adding status tracking. Existing records, full text, reasons and saved feedback keep working.

04 / Option 3 · Track outstanding choices

Decided / Still to decide

Make ownership and unresolved work explicit in separate sections.

Useful when choices remain open

Every unresolved choice names who should answer and whether implementation must wait. Completed choices move into “Decided”.

A larger product change

This needs stored status, ownership, transitions and rules for existing plans. The app cannot safely derive those from old prose.

The open question shown here is invented to demonstrate the option. Nothing in the supplied screenshot establishes an outstanding choice.

Agent treatment: structured status and owner fields, plus an explicit rule for which choices block implementation.

05 / Choose the smallest complete answer

Option 2 fits the current product.

Option Human reads Agent receives Cost / limitation
1 · Agreed decisions These were agreed Guidance to follow choices Very small; approval implication
2 · Decisions to follow These choices apply to this work The same instruction, with conflict handling Small; no status tracking
3 · Decided / Still to decide What remains and who answers Stored status, owner and blocking rules Larger; new data and migration policy

What the draft changes

Rename the section, add one sentence, and render full choices and reasons as a plain list. Keep the section absent when there are no required decisions.

Keep the existing decision IDs and feedback matching. No database migration or new approval state.

What it cannot establish

The app does not inspect old prose to decide whether a choice was really settled. A contradictory or unanswered question inside a decision still needs correction by the planner.

Changing an existing agent's installed skill is a separate installation step. The server's tool description supplies the guidance to clients that refresh tool discovery after deployment.

06 / Same meaning in the agent handoff

Follow the choice. Raise a conflict.

For the implementing agent

“Required decisions are choices to follow during implementation, not open questions or proof of human approval. Raise conflicts before changing a recorded choice.”

Added to the get_work_item tool description and explained in the bundled skill.

For the planning agent

Store chosen outcomes in decisions. Keep unresolved questions in the planning conversation. If the implementer should make a choice, put that delegation and its limits in the work item's requirements.

This distinguishes “follow this” from “choose within these limits” without inventing approval.
